# Handoff — restart, or rebuild after a wipe (M1 Max)

**Written 2026-10-12.** Read the top section first; it decides which path you're on.

## 0. Before you restart or erase — back up these five things

A wipe destroys device identity and every durable session. This takes about two minutes and is the
only irreversible step. Copy to an external drive, iCloud, or another Mac:

| What | Why it cannot be recreated | Command |
|---|---|---|
| `~/.dpi/` (5.1 MB) | Device tokens, `network.sqlite` registry, **every session database and App State** | `cp -R ~/.dpi ~/Backup-dpi` |
| `~/Projects/durable-pi/.env` | The OpenRouter inference key | `cp ~/Projects/durable-pi/.env ~/Backup-dpi-env` |
| `~/.claude/.env` | Your canonical secrets file | `cp ~/.claude/.env ~/Backup-claude-env` |
| `~/.ssh/` | The M6 key (`id_ed25519_dpi_m6`) — regenerate + `ssh-copy-id` if lost, but the config is easier to keep | `cp -R ~/.ssh ~/Backup-ssh` |
| `~/Library/LaunchAgents/dev.dpi.*.plist` | The Hub plist was written by hand and is **not** regenerated by any command | `cp ~/Library/LaunchAgents/dev.dpi.*.plist ~/Backup-dpi/` |

Also confirm your real work is pushed: `git -C ~/Projects/durable-pi push` and the same for
`toolbelt`, `Foundry`, `foundry-doctrine`, `cognitive-harness`.

**Do not erase the Mac without `~/.dpi` and the two `.env` files copied off.**

## 1. About System Settings (read before deciding to erase)

**Symptom:** System Settings will not open on the M1 Max.

**What was actually measured**, in a shell that is *not* in your GUI session:

- `/System/Applications/System Settings.app` **exists**, and its executable
  `Contents/MacOS/System Settings` **exists**.
- Launching it returns `kLSNoExecutableErr: The executable is missing`.
- `codesign --verify --strict` returns `CSSMERR_TP_NOT_TRUSTED` — for System Settings, Mail, Notes,
  Calculator, `/bin/ls`, `/usr/bin/sqlite3`, `/usr/libexec/sysmond`. **Everything.**
- `security dump-trust-settings` says: `No keychain is available. You may need to restart your
  computer.`
- `pgrep` cannot read the process list; `launchctl print gui/$(id -u)` is *Operation not permitted*.

**Honest reading:** "everything fails signature verification" is not a normal Mac, but it is also
exactly what a shell *outside the GUI security session* would report. The clock is correct, `csrutil`
says SIP is enabled, the system volume is still `sealed`, and `security verify-cert` on a normal
certificate says "No error." So the trust *chain* is probably intact, and the most likely real fault
is something narrower: the GUI session's keychain/trust services, or LaunchServices state.

**Therefore: try a restart before you erase.** A restart is free; an erase without a backup is not.

### Cheap ladder, in order — stop as soon as one works

1. **Restart normally.** Then try System Settings.
2. **Restart in Safe Mode** (hold the power button → *Continue* holding → *Options* is Recovery;
   for Safe Mode: restart and hold **Shift** until the login window). Log in, try System Settings,
   then restart normally. Safe Mode rebuilds caches and often clears exactly this.
3. If it opens in Safe Mode but not normally, it is a login-item or cache problem, not a corrupted
   install — do not erase.
4. **Recovery → Reinstall macOS** (hold power button; choose *Options*). This **repairs system files
   and keeps your data**. Run it *before* considering Erase.
5. **Erase All Content and Settings** only if 1–4 fail, and only after Step 0.

## 2. After a normal restart (nothing wiped) — what comes back on its own

You do nothing. Log in — that is the trigger everything waits on.

| Thing | Comes back by itself? | How to check |
|---|---|---|
| Cockpit (Hub) `:4781` | **Yes** — `dev.dpi.hub`, KeepAlive | open `http://100.116.127.70:4781` |
| Laptop backend `:4780` | **Yes** — `dev.dpi.backend`, KeepAlive | `launchctl list \| grep dpi` |
| M6 backend | **Yes** — its own launchd agent, if the M6 is powered and logged in | `just net status` from `~/Projects/durable-pi` |
| Cloud VM (compass) | **Yes** — systemd on the VM, independent of you | `just net status` |

If the Hub is missing after a restart: `launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.dpi.hub.plist`.
If `local` is missing: from `~/Projects/durable-pi`, run `just net up local`.

**Reminder from the audit:** launchd agents start at *login*. With FileVault on and no auto-login,
a reboot means nothing is running until you log in. That is expected, not a fault.

## 3. After a full erase — rebuild from zero

Paths assume Homebrew lands in `/opt/homebrew` (Apple silicon).

### 3a. Base toolchain

```bash
xcode-select --install                       # Command Line Tools (needed by Homebrew)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
eval "$(/opt/homebrew/bin/brew shellenv)"    # add to ~/.zprofile too
brew install node just ripgrep               # node 26, just 1.58, ripgrep 15
node --version && just --version && rg --version
```

`ripgrep` matters: the agent shells use the launchd PATH, and `rg` must be a real binary on it —
Pi's bundled copy at `~/.pi/agent/bin/rg` is *not* on that PATH.

### 3b. Tailscale + node

1. Install Tailscale from the App Store or `brew install --cask tailscale`, sign in with the same
   account, and confirm all three machines are in the tailnet.
2. Recreate your `~/.ssh/config` `Host m6` block (HostName, `HostKeyAlias`, user `paulm6`,
   `IdentityFile ~/.ssh/id_ed25519_dpi_m6`).
3. Restore `~/.ssh` from backup — or regenerate the key and re-run `ssh-copy-id` to the M6.

### 3c. The repositories

```bash
mkdir -p ~/Projects && cd ~/Projects
git clone https://github.com/DevPaulE/durable-pi.git
cd durable-pi && git log --oneline -3        # expect 5d63860 or later on main
cp .env.example .env                          # then paste OPENROUTER_API_KEY from your backup
chmod 600 .env
cp dpi-network.example.yaml dpi-network.yaml  # then edit: devices + env_keys + env (below)
just install
```

`dpi-network.yaml` must end up like this (it is gitignored, which is why a wipe loses it):

```yaml
devices:
  local:
    name: M1 Max
    kind: local
    service: launchd
    env_keys: [OPENROUTER_API_KEY]
    env:
      DPI_PROVIDER: openrouter
      DPI_PROVIDERS: openrouter,faux
  m6:
    name: Mac mini
    kind: ssh
    ssh: m6
    url: http://<M6 tailnet ip>:4780
    host: <M6 tailnet ip>
    service: launchd
    start_dirs: [~/dpi-work]
    env_keys: [OPENROUTER_API_KEY]
    env:
      DPI_PROVIDER: openrouter
      DPI_PROVIDERS: openrouter,faux
  compass:
    name: exe.dev VM
    kind: exe-dev
    vm: compass
    start_dirs: [~/dpi-work]
```

Then, in order:

```bash
just net up local       # writes ~/.dpi/backend.env, installs dev.dpi.backend
just hub build          # the UI the hub serves
# recreate the Hub agent by hand (it is not generated for you):
#   ProgramArguments: /opt/homebrew/bin/node <repo>/apps/dpi-playground/node_modules/tsx/dist/cli.mjs apps/dpi-playground-hub/src/main.ts
#   WorkingDirectory: <repo>/apps/dpi-playground
#   Env: DPI_HUB_HOST=<this Mac's tailnet ip>, DPI_HUB_PORT=4781, HOME, PATH, NODE_NO_WARNINGS=1
#   RunAtLoad + KeepAlive, working stdout/stderr -> ~/.dpi/logs/hub.log
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/dev.dpi.hub.plist
just net status         # expect 3 devices online
```

**Only restore `~/.dpi` from backup if you want the old sessions and device tokens.** If you restore
it, skip `just net up local`'s token generation concerns — the tokens come back with it.

### 3d. Pi, and getting back to this conversation

```bash
# pi
curl -fsSL https://bun.sh/install | bash
bun install -g @earendil-works/pi-coding-agent
pi --version
```

Then restore the LifeOS layer: `~/.claude` (which holds `CLAUDE.md`, `LIFEOS/`, your skills and
`~/.claude/.env`), and `~/Projects/toolbelt` (the LifeOS map at `toolbelt/LIFEOS.md`).
Run `pi` from `~/.claude` so the AGENTS.md context loads.

### 3e. Verify you are actually back

```bash
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:4780/healthz    # 200
curl -s -o /dev/null -w '%{http_code}\n' http://<tailnet ip>:4781/        # 200
just net status                                                            # 3 online
```

## 4. Known-open items you are inheriting (do not be surprised by them)

From `~/dpi-work/AUDIT-2026-10-12-opus.md` (12 verified findings):

- The **exe.dev VM is reachable from the public internet** (`https://compass.exe.xyz/healthz` → 200).
  Token-gated, but it contradicts the "no public port" boundary. Fix or amend the boundary.
- The **Hub has no authentication** — `guard.ts` only checks Origin when an `Origin` header is sent.
  The tailnet ACL is the entire control. Keep the Hub bound to the tailnet only.
- A **boot-time regression writes an empty model id** (`Store.open` routes before loading the catalog).
- A **pi-ai catalog change crash-loops the backend**.
- `jev-damage-control` uses the **device** default, not the session, and fails open.

Full report: `~/dpi-work/AUDIT-2026-10-12-opus.md`. Fix scope: `~/dpi-work/SCOPE-fixes-2026-10-12.md`.

## 5. Do-not-forget

- Never bind the Hub or a backend to `0.0.0.0`. Tailnet only.
- `.env` values: no surrounding quotes, no leading/trailing spaces.
- A **provisioning** OpenRouter key cannot run inference (`401 User not found.`) — use an inference key.
  `GET /api/v1/models` is public, so a full model list proves nothing about a key.
- Never log out of the M6; the agent is a `gui/<uid>` LaunchAgent.
- Foundry is a no-write zone.
